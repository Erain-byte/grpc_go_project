# User 服务初始化与注册实现指南

## 1. 本阶段目标

Keycloak 负责账号注册、密码、登录、刷新 Token 和退出登录。User 服务只负责创建和维护本地业务用户。

本阶段只完成一条最小闭环：

```text
Keycloak 注册并登录
    -> Gateway 验证 Access Token
    -> POST /user/initialize
    -> Gateway 转发原始 Token
    -> User 服务再次验证 Token
    -> 根据 Token sub 查找本地用户
    -> 不存在时生成 user_id 并写入对应分片
    -> 返回 UserInfo
```

本阶段不实现密码注册、登录、刷新 Token、退出登录，也不在 User 表保存密码。

## 3. 开始编码前需要确认的设计

### 3.1 用户 ID

建议使用雪花 ID：

```text
user_id = Snowflake.NextID()
table_index = user_id % 8
table_name = users_XX
```

需要增加配置：

```yaml
id_generator:
  node_id: 1
```

本地固定使用 `1`。生产环境中，同一时间运行的 User 实例必须使用不同的 `node_id`。后续可以由配置中心或 Consul 分配；当前阶段先通过环境变量 `USER_SNOWFLAKE_NODE_ID` 注入。

建议使用成熟雪花算法库，不在业务项目里重新实现位运算和时钟回拨处理。

### 3.2 本地用户何时创建

推荐使用显式初始化接口：

```http
POST /user/initialize
Authorization: Bearer <access-token>
```

前端在 Keycloak 登录成功后调用一次。接口必须幂等，重复调用只返回已有用户。

不建议在认证中间件中创建用户，因为认证中间件只应该验证身份，不应该产生数据库写入。

### 3.3 身份数据来源

只信任 User 服务自己验证后的 Access Token Claims：

| 本地字段 | Token Claim |
|---|---|
| `keycloak_subject` | `sub` |
| `username` | `preferred_username` |
| `email` | `email`，允许为空 |

Gateway 传递的 `x-user-id`、`x-user-name` 可以用于日志，但不能代替 User 服务对 Token 的验证结果。

## 5. 第一步：实现认证身份 Context

创建 `user/internal/auth/context.go`：

```go
type Identity struct {
    Subject   string
    Username  string
    Email     string
    Role      string
    SessionID string
    TokenID   string
}

func NewContext(ctx context.Context, identity Identity) context.Context
func FromContext(ctx context.Context) (Identity, bool)
```

Context key 必须使用包内私有类型，不能直接使用字符串，避免和其他包冲突。

## 6. 第二步：实现 User JWT 拦截器

可以参考 `admin/internal/middleware/auth.go`，但不要直接依赖 Admin 包。

职责：

1. 健康检查直接放行。
2. 根据 gRPC FullMethod 读取 Proto 的 `common.v1.auth` 配置。
3. 从 incoming metadata 读取唯一的 `authorization`。
4. 解析 `Bearer <token>`。
5. 使用 Keycloak JWKS 验证 RS256 签名。
6. 验证 `issuer`、`audience`、过期时间。
7. 从 Realm Roles 选择应用角色。
8. 判断角色是否允许调用该 RPC。
9. 把经过验证的 Identity 写入 Context。

Claims 至少包含：

```go
type accessTokenClaims struct {
    PreferredUsername string      `json:"preferred_username"`
    Email             string      `json:"email"`
    EmailVerified     bool        `json:"email_verified"`
    SessionID         string      `json:"sid"`
    RealmAccess       realmAccess `json:"realm_access"`
    jwt.RegisteredClaims
}
```

不要只相信 Gateway 传来的 `x-user-role`。Gateway 和 User 都验证 Token，形成边界层和业务服务的双重校验。

## 7. 第三步：实现 ID Generator

定义小接口，避免 Service 绑定某个雪花库：

```go
type Generator interface {
    NextID() (int64, error)
}
```

雪花实现负责：

- 初始化并验证 Node ID 范围；
- 返回正数 `int64`；
- 将库错误转换为明确错误；
- 作为进程级单例放入 `ServiceContext`。

不要在每次请求中创建雪花 Node，否则可能生成重复 ID。

## 8. 第四步：扩展 ServiceContext

当前 `ServiceContext` 只有 Config、Consul 和 Redis。建议增加：

```go
type ServiceContext struct {
    Config   *config.Config
    Consul   *consul.ConsulRegistry
    Redis    redis.RedisClient
    Database *databases.GormClient
    Router   *sharding.UserRouter
    IDs      idgen.Generator
    Logger   *zap.Logger
}
```

这些对象适合放入 ServiceContext，因为它们满足至少一项：

- 创建成本较高，需要整个进程复用；
- 需要统一关闭；
- 并发安全并由多个 Handler/Service/Repository 使用；
- 生命周期与进程一致。

具体请求、事务对象、protobuf Request 不放入 ServiceContext。

同时把拼写 `Conusl` 修正为 `Consul`。这是字段重命名，需要同步所有引用。

## 9. 第五步：实现 User Repository

建议接口：

```go
type UserRepository interface {
    FindBySubject(ctx context.Context, subject string) (*model.User, error)
    EnsureFromIdentity(ctx context.Context, identity auth.Identity) (*model.User, bool, error)
}
```

第二个返回值表示是否为本次新建。

### 9.1 查询已有用户

```text
sub
 -> 查询 user_identity_index
 -> 得到 user_id + table_index
 -> Router.TableNameByIndex(table_index)
 -> 查询 users_XX
```

必须验证索引中的 `table_index` 与 `user_id % 8` 一致。如果不一致，应返回数据完整性错误，不能继续查询错误分片。

### 9.2 首次创建事务

所有表都在同一个 PostgreSQL 数据库，因此使用本地事务即可：

```text
生成 user_id
 -> 计算 table_index
 -> BEGIN
 -> INSERT user_identity_index ON CONFLICT DO NOTHING
 -> 如果成功插入：INSERT users_XX
 -> COMMIT
```

推荐先插入全局索引，再插入分片用户。全局索引的 `keycloak_subject` 主键用于处理并发初始化。

### 9.3 并发幂等

同一个用户可能同时发起两个初始化请求：

```text
请求 A：成功插入 identity index，然后写 users_XX
请求 B：ON CONFLICT DO NOTHING，RowsAffected == 0
请求 B：重新查询 identity index 和 users_XX，返回已有用户
```

不能采用“先查询，不存在再直接 Create”作为唯一保护，因为两个请求可能同时查询到不存在。

建议使用：

```go
clause.OnConflict{
    Columns:   []clause.Column{{Name: "keycloak_subject"}},
    DoNothing: true,
}
```

若当前事务成功插入全局索引，但写分片表失败，整个事务必须回滚，不能留下孤立索引。

## 10. 第六步：实现 InitializeUser Service

创建 `user/internal/service/initialize_user.go`。

职责：

1. 从 Context 获取认证 Identity。
2. 校验 `Subject` 和 `Username` 非空。
3. 调用 Repository 的幂等初始化方法。
4. 将 Model 转成 Proto。

Service 不负责：

- 解析 JWT；
- 拼接物理表名；
- 创建数据库事务；
- 从 HTTP Header 读取数据。

模型转换时注意：

```go
timestamppb.New(user.CreatedAt)
```

可空时间和可空字符串需要先判断 nil。

## 11. 第七步：实现 User Handler

```go
type UserHandler struct {
    userv1.UnimplementedUserServiceServer
    initialize *service.InitializeUserService
}
```

构造函数接收 `ServiceContext`，初始化 Service。RPC 方法只转发：

```go
func (h *UserHandler) InitializeUser(
    ctx context.Context,
    req *userv1.InitializeUserRequest,
) (*userv1.InitializeUserResponse, error) {
    return h.initialize.InitializeUser(ctx, req)
}
```

增加编译期接口断言：

```go
var _ userv1.UserServiceServer = (*UserHandler)(nil)
```

## 12. 第八步：注册 gRPC 服务

修改 `user/internal/server/grpc.go`：

1. `NewGrpcServer` 同时接收 Config 和 ServiceContext。
2. 创建 AuthInterceptor。
3. 配置 Unary 和 Stream Interceptor。
4. 配置最大收发消息尺寸。
5. 注册 Health Server。
6. 创建 UserHandler。
7. 调用 `userv1.RegisterUserServiceServer`。
8. 实现 `Start()` 和带超时的 `Stop(ctx)`。

推荐拦截器顺序：

```text
Request ID -> Error Handler -> Auth -> Rate Limit -> Handler
```

User 当前还没有这些拦截器时，可以先只接 Auth，随后再补 Request ID、统一错误和限流，但不要为了赶进度跳过 Token 验证。

## 13. 第九步：组装 app.Run

建议启动顺序：

```text
加载配置
 -> 初始化 Logger
 -> 初始化 PostgreSQL 并 Ping
 -> 初始化 Router
 -> 初始化 Snowflake Node
 -> 初始化可选 Redis
 -> 初始化 Consul
 -> 创建 ServiceContext
 -> 创建 gRPC Server
 -> 启动 gRPC
 -> 注册 Consul
 -> 等待退出信号
```

关闭顺序与创建顺序相反：

```text
Consul 停止补注册
 -> Consul 注销服务
 -> gRPC GracefulStop
 -> Redis Close
 -> PostgreSQL Close
 -> Logger Sync
```

`cmd/user/main.go` 最终只保留：

```go
func main() {
    if err := app.Run(); err != nil {
        slog.Error("user service stopped", "error", err)
        os.Exit(1)
    }
}
```

## 14. 第十步：补 Gateway 路由

`gateway/internal/forwarder/user.go` 已经存在 `InitializeUser`，还需要在 `routes_user.go` 注册：

```go
protected.POST(
    "/initialize",
    handler.NewGrpcHandler[
        pbUser.InitializeUserRequest,
        pbUser.InitializeUserResponse,
    ](userForwarder.InitializeUser).Handle,
)
```

User 路由建议只允许 `user`：

```go
userRoles := cfg.Auth.AccessToken.RolesMatching("user")
```

空 protobuf Request 必须允许 HTTP 空 Body。Gateway 的通用 Handler 应忽略 `io.EOF`：

```go
if err := c.ShouldBindJSON(req); err != nil && !errors.Is(err, io.EOF) {
    // 返回 400
}
```

## 15. 错误语义

建议统一映射：

| 场景 | gRPC Code |
|---|---|
| Token 缺失或无效 | `Unauthenticated` |
| 角色不允许 | `PermissionDenied` |
| `sub` 或用户名缺失 | `InvalidArgument` |
| 本地用户不存在 | `NotFound` |
| 唯一键并发冲突且重查失败 | `Aborted` |
| PostgreSQL 暂时不可用 | `Unavailable` |
| 索引和分片数据不一致 | `DataLoss` 或内部数据完整性错误 |

不要把数据库原始错误、SQL、DSN 或 Token 返回给客户端。

## 16. 必须编写的测试

### Router

- 正数 ID 正确映射到 `users_00` 至 `users_07`；
- 非正数 ID 返回错误；
- 非法 table index 返回错误。

### Repository

- 已存在 subject 能通过索引查到正确分片；
- 首次创建同时写入索引和分片；
- 分片写入失败时索引也回滚；
- 同一个 subject 并发初始化只产生一个用户；
- 索引 table_index 与 user_id 不一致时报错。

### Auth Interceptor

- 没有 authorization metadata 返回 Unauthenticated；
- Token 过期返回 Unauthenticated；
- audience 不匹配返回 Unauthenticated；
- `user` 能调用 InitializeUser；
- 非允许角色返回 PermissionDenied；
- Health Check 不要求 Token。

### Service

- Context 没有 Identity 时失败；
- 已存在用户返回 `newly_created=false`；
- 新用户返回 `newly_created=true`。

## 17. 手工联调顺序

1. 启动共享 `postgres`，并确认 `user_service` 数据库已经创建。
2. 执行 User 数据库迁移。
3. 启动 Keycloak、Consul、Gateway、User。
4. 使用 Keycloak `user-test` 登录获得 Access Token。
5. 调用 `/user/initialize`。
6. 验证 `user_identity_index` 新增一行。
7. 根据 `table_index` 验证对应 `users_XX` 新增一行。
8. 使用同一个 Token 再调用一次。
9. 验证没有新增第二个用户，响应 `newly_created=false`。
10. 调用 `/user/info` 验证能通过索引读取分片数据。
